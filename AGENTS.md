# Aether

Aether is a Terraria utility client: a modified build of Terraria (the Linux Steam build's `Terraria.exe`), currently based on the version pinned in `tools/base.json` (`game_version`), that runs on .NET 10 on every OS (the game itself ships on Mono and .NET Framework).
It is **not** a decompilation project.
Aether's MIT-licensed client source lives in `client/` and is tracked directly.
Changes to existing game files live in `patches/`.
The game's own code and data are regenerated locally from each developer's copy of Terraria.
Notes on the game's modules live in `AGENTS.md` files under `src/Terraria/`; read the nearest one before editing a module.

## Pre-release compatibility

Until Aether's first formal release, prefer breaking changes that simplify the design or fix a flawed contract over preserving compatibility with earlier Aether builds.
Remove superseded APIs, CLI options, manifest fields, and formats when replacing them, and update in-tree callers, examples, tests, and documentation in the same change.
Add compatibility shims, aliases, or migrations only for an explicit requirement.
Honor existing vanilla Terraria compatibility requirements and reject unreadable saves before overwriting them.

## Exploit policy

Leave exploits present in vanilla Terraria for Re-Logic to fix, on both the client and the server.
Aether allows client and server exploits, provided Aether changes do not introduce remote code execution (RCE).

## Patch workflow

```bash
./aether download  # optional: fetch the pinned Linux build with SteamCMD into .aether/game/
./aether setup     # first time / after a clone: decompile your Terraria.exe into .base/ + lib/, build src/
./aether diff      # after editing src/: regenerate patches/ (the pre-commit hook also does this)
./aether apply     # rebuild src/ from .base/ + patches/ (build does this itself when patches/ changed, e.g. after a pull)
./aether status    # what you've changed vs the base, and whether patches/ is current
./aether run       # build the client and play it (saves go to .aether/saves/)
./aether build     # just build (bin/<Debug|Release>/net10.0/); --target lin64|win64|mac64|macarm|mac|all: also package dist/<target>/
./aether launch    # just play the most recent build (Debug or Release), no build
./aether screens   # build and open the gallery of Aether's retained-mode title-menu screens (MODE: just that one)
./aether control   # send input/commands to a client started with --mcp PORT (run, launch, screens)
./aether update    # move the base to the newest Terraria on Steam and re-apply the patches (--check: just look)
```

`./aether` needs [uv](https://docs.astral.sh/uv/) (plus git, the .NET SDK, `diff`, `patch`, and the GitHub CLI `gh`, logged in, which `setup` uses to fetch FNA's native libraries); uv installs the CLI's Python dependencies from `uv.lock` on first run.

- **Put new C# files in the tracked project under `client/`**.
  Aether features that compile into Terraria live in `client/Terraria/Aether/`.
  The Windows FNA adapter compiles into ReLogic from `client/ReLogic/FnaWindowsPlatform.cs`.
- **Edit `src/` when changing an existing game file** in Terraria or ReLogic.
  Commit the generated unified diffs in `patches/`.
  The generated tree is gitignored apart from its `AGENTS.md` files, and `aether diff` rejects new C# files there.
  After pulling the source layout change, run `./aether apply` to clear the previous generated copies.
  Move any local edits to those copies into their new locations first.
- `.base/` is the pristine decompile and `lib/` the extracted DLLs.
  Both are gitignored and regenerated by `setup`.
  Never edit `.base/`; it's the reference all patches are made against.
- The **pre-commit hook** (prek, installed by `setup`; hooks in `prek.toml`) first runs `aether pre-commit`, which runs `./aether diff`, stages `patches/`, then refuses the commit if anything under `src/` (except `AGENTS.md`), `.base/` or `lib/` is staged, if a binary or game-asset type (`.dll`, `.exe`, `.xnb`, …) is staged, or if a staged `.cs`/`.json`/`.tsv` file is a verbatim copy of a decompiled file.
  Never `git add -f` inside `src/`, and don't bypass the hook with `--no-verify`.
  Commit messages must follow Conventional Commits (checked by conventional-pre-commit and by cocogitto, `cog`, which must be installed).
- The hook regenerates patches from **all** of `src/`, so every commit includes all current game source edits.
  To commit only some patches, stash the other edits out of `src/` first.
  Stage tracked Aether source in `client/` separately.
- `apply` refuses to overwrite `src/` edits that aren't captured in `patches/` (run `diff` first, or `apply --force` to discard them).
  If a patch doesn't apply (e.g. after a game update), it leaves `src/<file>.rej`.
  Fix the file by hand, delete the `.rej`, then run `./aether diff`.
- Keep diffs small: edit in place and keep the decompiler's formatting.
  Reformatting or renaming produces huge patches that break on every regeneration.
- **Versions:** `tools/base.json` pins the build the base is decompiled from (`game_version`, Linux depot manifest, `Terraria.exe` sha256, plus the macOS/Windows manifests), and `setup` checks the exe against it.
  `patches/GAME_VERSION` records the game version the patches are known to apply to; it's committed with them.
  `diff` sets it to the base's version (patches made against the base apply to it by definition), and so does an `apply` or `setup` in which every patch applies; `status` and `diff --check` report when the two differ. ilspycmd is pinned in `.config/dotnet-tools.json`.
  The decompile recipe lives in `tools/aether/decompile.py` (`build_base`; libraries in `PATCHABLE_LIBRARIES` are decompiled too, into `src/<name>/`): net40 reference assemblies plus the extracted DLLs (not the game's Mono `mscorlib`, which makes ILSpy emit `MathF.PI`), `--nested-directories -p`, leading tabs → 4 spaces, CRLF → LF for resources.
  Changing the recipe changes `.base/`; bump `recipe` in `base.json`, regenerate, and refresh all patches.
- The game location defaults to `aether download`'s copy in `.aether/game/` if there is one, otherwise `~/.local/share/Steam/steamapps/common/Terraria`; override it with `--game-dir` or `$TERRARIA_DIR`.
- `download` runs SteamCMD's `download_depot` for the Linux depot and manifest pinned in `tools/base.json` (`steam`), so it always gets the pinned build rather than the current one, and works on any OS that runs SteamCMD.
  `--platform macos|windows` fetches those builds (pinned under `platforms`) into `.aether/game-<platform>/`; they only supply runtime files to `run`, never the base.
  It only passes the Steam username (`--username` / `$STEAM_USERNAME` / prompt); SteamCMD asks for the password and Steam Guard code itself and caches the login.
  SteamCMD comes from PATH (`steamcmd` / `steamcmd.exe`), `~/.steam/steamcmd/`, or is installed from Valve's build for the host OS (Linux and macOS tarballs, Windows zip) into `.aether/steamcmd/`; the download is found by searching that SteamCMD's folder for `steamapps/content/app_105600/depot_105602`, which covers each OS's layout.

## Build and run

```bash
dotnet build Aether.slnx -c Debug
```

- Targets **.NET 10** (`net10.0`, `Microsoft.NET.Sdk`; `RollForward` lets a newer runtime run it), on every OS: Mono and .NET Framework, which the game's own builds use, aren't involved.
  Expect 0 errors and ~700 warnings (obsolete APIs, unused locals, unreachable code).
  These are normal for decompiled code, so don't "fix" them unless you're already editing that code.
  The game's XNA-era code (its WinForms window, used only when `Program.IsXna`) compiles against stand-ins in `client/Terraria/Aether/Compat/` that throw if reached.
  Windows runs on FNA through `FnaWindowsPlatform`.
  On .NET, `Thread.Abort` doesn't exist (the LAN broadcast thread stops cooperatively).
- **Frame rate:** the game updates 60 times a second, but frames aren't held to that: Aether's "Uncapped FPS" setting (`GraphicsSettings.UncappedFps`) draws them as fast as possible, and otherwise every vsync (`Main.DoUpdate`).
  Vanilla's Frame Skip setting is gone from the settings menus and has no effect.
  The mouse's position (not its buttons or wheel) is read again for every frame (`PlayerInput.RefreshMousePosition` at the start of `DoDraw`, and `UserInterface.Draw` takes it in UI coordinates from `PlayerInput.UIMousePosition`), so what follows it while drawing (the map being dragged, scrollbars, the item on the cursor, tooltips) moves every frame; `Main.lastMouseX/Y` stay the previous update's position for updates.
  Animation advanced while drawing counts 60 Hz ticks, not frames: add `Aether.Graphics.VisualAnimationTime.WholeTicks` (text cursors' `textBlinkerCount` does), or it runs faster with the frame rate.
- The client output is `client/Bootstrap/bin/Debug/net10.0/` with the `Aether.Bootstrap` apphost (`Aether.Bootstrap.exe` on Windows), `Terraria.dll`, the mod API, runtime metadata, FNA and supporting libraries.
  **Run it with `./aether run`** (build + launch; `--release`, `--save-dir`, `--real-saves`, `--platform-dir`; arguments after `--` go to the game; Steam must be running), or separately with `./aether build` and `./aether launch` (runs whichever of the Debug/Release builds is newer).
  It needs the .NET 10 runtime installed (the SDK has it), and rebuilds `.aether/run/` around the client with **Aether's FNA** (`lib/FNA.dll` and the matching natives in `lib/fnalibs*/`), which replaces each build's older FNA 26.3 and its SDL3/FNA3D/FAudio:
  - **Linux:** the client with every native library next to it (`lib/fnalibs/lib64/` over the game's Steam and file-dialog libraries from its `lib64/`), plus symlinks to the Linux build's `Content/` and other files; none of its Mono runtime (MonoKickstart, Mono's `*.dll`s, its `Terraria.exe` and FNA).
    The vanilla server that Host & Play starts is a separate Mono program needing its own, older FNA, so it gets the game's layout in `server/` (Aether's patch to `Main.cs` starts `server/TerrariaServer`), with copies of its launchers: MonoKickstart finds `lib64/` relative to its real path.
  - **macOS:** a copy of the **macOS** build's `Terraria.app` (`--platform-dir`, default `.aether/game-macos/` from `./aether download --platform macos`, else the Steam install) with the client in `Contents/Client/` (with `lib/fnalibs-apple/osx/`, the bundle's Steam library and a link to `Contents/Resources/Content/`), started by a `Contents/MacOS/Terraria` script.
    The macOS bundle supplies its own shaders and XACT audio banks.
    The vanilla server keeps the bundle's `MacOS/` (copied) and `Resources/` (linked), where the game starts it from (`../MacOS/TerrariaServer`).
  - **Windows:** the client links the **Linux** build's `Content/` (the Windows build's is XNA's: Reach-profile images and XNA-compiled shaders), and copies `lib/fnalibs/x64/` and `lib/fnalibs/D3D12/` (FNA3D's Direct3D 12 Agility SDK), plus the official 64-bit Steamworks.NET and `steam_api64.dll` from `lib/steamworks/` (pinned in `tools/steamworks.json`: Terraria embeds that same Steamworks.NET 2024.8.0 release unmodified, so its x64 build is the drop-in match).
    That Steamworks.NET sits next to the client, which loads a library next to it in preference to the embedded one (the Linux build).
    The Windows build (`--platform-dir`, `.aether/game-windows/` from `./aether download --platform windows`, or the Steam install) is optional: it only supplies the vanilla 32-bit `TerrariaServer.exe` (it still runs on .NET Framework, as a separate process) and its own `steam_api.dll`, for Host & Play.
    Its other natives are 32-bit and unused: `ReLogic.Native.dll` is only the XNA IME, the RGB SDKs fail silently, and there's no x64 `nfd.dll`, so Aether's patch to `NativeFileDialog.cs` makes the file browser (resource-pack/world import) return nothing instead of crashing.
  Saves default to `.aether/saves/`, so your real saves are left alone; the startup log should report `FNA3D v26.11.0` and `FAudio v26.11.0`. macOS and Windows are implemented but not yet tested on real machines (Linux and the `lin64` target are).
- **`./aether build --target`** (`lin64`, `win64`, `mac64` (Intel), `macarm` (Apple silicon), `mac` for both, or `all`; repeatable) also packages `dist/<target>/`: the client published **self-contained** for that OS (`dotnet publish -r linux-x64|win-x64|osx-x64|osx-arm64`, into `.aether/publish/`, with the .NET runtime, so players don't need .NET installed) in the same layout as the run folder, but copied.
  It can be built on any OS: `lin64` and `win64` need the Linux build (`--game-dir`), the mac targets the macOS build (`./aether download --platform macos` or `--platform-dir`, which needs the targets to be one OS's); another OS's Steam install isn't looked for.
  The macOS apphost isn't signed when published elsewhere: on Apple silicon, sign the bundle on a Mac (`codesign --force --deep -s - Terraria.app`) before running it.
  `dist/` contains the game's files: it's gitignored and for playing on your own machines, not for distributing.
- The bootstrap discovers local mod archives before loading the client.
  See [the mod authoring guide](docs/modding.md).
- The client exe has no headless mode: `Main.dedServ` is only set in the separate server build, so any runtime test opens a game window.
  To drive that window without focusing it or sending system input, start it with `--mcp PORT`: the client then serves the `aether-game` MCP server itself (`.mcp.json`), which agents use directly and `./aether control` sends commands through (see `.agents/skills/aether-game/SKILL.md`).
  Use [remote UI automation](docs/ui-automation.md) to inspect and act on retained components by ID.
- **Logging:** Terraria and Aether log through Serilog (`client/Modding/AetherLog.cs`), which the bootstrap starts first thing; `Serilog` is shared with mods like FNA.
  Terraria's and ReLogic's own prints are log events (`Aether.GameLog.Terraria`, `ReLogic.ReLogicLog.Log`; sources `Terraria` and `ReLogic`), except the dedicated server's prompts written without a newline (`Console.Write`), and FNA's (`FNALoggerEXT`) and SDL's (`SDL_SetLogOutputFunction`) logs are routed in too (`GameLog.CaptureLibraries`, from `Program.SetupLogging`).
  Other console output (native libraries' own prints aside, which bypass .NET) still reaches the console unchanged and is also logged a line an event (source `Console`).
  Aether's own events (`AetherLog.For("Aether.Something")`, mods' `ModLog.For(modId)`) go to standard error as `[time LVL] Source: message`, Information and above, Debug too with `-mixindebug`, so standard output stays the game's.
  Terraria's `-logfile [dir]` writes everything, Debug included, to `Logs/Log_<time>.log` through Serilog's file sink (in place of ReLogic's `ConsoleOutputMirror`), including the events from before the game opens it.
  At startup the bootstrap logs the Aether and Terraria versions, the loaded mods as a tree of their dependencies, and the mixins applied (each at Debug, then a summary); the API logs what it registered.
- **Frame profiling:** `Aether.Profiling.FrameMeter` measures every drawn frame from one hook at the end of `Main.Draw` (`FrameProfiling.EndFrame`): real frame time, the main thread's CPU time, the GPU time (Linux, through the patched FNA3D; n/a elsewhere) and what the .NET runtime did (allocations, collections, GC pauses, heap size, JIT compiles).
  Right Shift + F12 shows the profiler overlay (`ProfilerOverlay`), a Dear ImGui window (ImGui.NET, hosted by `Aether.Graphics.DearImGui.ImGuiHost` over the finished frame) with the frame rate and its 1% and 0.1% lows, a frame-budget bar, a frame time graph, frame/CPU/GPU time percentiles and the runtime's figures over the last two seconds.
  ImGui only runs while a window is shown, so the hidden overlay costs nothing but the measuring.
- **Finding allocations:** `--profile` (Linux; with `--mcp`) has .NET load Aether's allocation profiler at startup (`CORECLR_PROFILER*`), a CoreCLR profiler (`ICorProfilerCallback3`) compiled from `tools/aether/profiler/aether_profiler.c` into `.aether/profiler/` (needs `cc`).
  The control command `profile [FRAMES] [TOP] PATH` (MCP: `game_profile`) then records every managed allocation's class, size and call stack and writes the methods with the most bytes allocated under them and the top sites, per frame.
  Allocation tracking turns off the runtime's allocation fast paths for the whole run, so only compare profiled runs with each other.

## Dependencies and embedded resources

- **FNA** is pinned to one release in `tools/fna.json` (26.11): `setup` builds `FNA.Core.csproj` (its .NET build, whose `FNADllMap` reads `FNA.dll.config` to find the native libraries) from that commit with `tools/fna.patch` applied (cached in `.aether/fna/`; `build` builds it again when the pin or the patch changes) and downloads the matching native libraries (`fnalibs` and `fnalibs-apple`) from FNA's `fnalibs-dailies` CI build, verifying every file's hash (`build` downloads a package again when `lib/` no longer matches its pin).
  The game's own FNA (26.3) is only used to decompile, so `.base/` doesn't depend on the FNA version.
  The patch adds `Texture.SamplerEXT` (a texture's own sampler in SpriteBatch, for smooth fonts in a UI a mod point-samples), `Texture.EffectEXT` (a texture's own effect in SpriteBatch, given the batch's `MatrixTransform`; for mods' signed distance field text) and `SamplerState.PixelSnapEXT` (SpriteBatch puts unrotated sprites drawn with it on whole pixels, and, while its `PixelScaleEXT` is set, evenly scaled ones at a whole multiple of that many pixels per texel; for mods), `Mouse`/`Keyboard`/`GamePad.StateFilterEXT` (what `GetState` returns passes through them; `SyntheticInput` injects input there, so everything reading FNA's input sees it) and keeps 26.3's leniency the game depends on: a disposed `SoundEffectInstance` reports `Stopped` and ignores `Stop`/`Pause` (26.11 throws, and Terraria disposes finished instances it still holds, so their sounds stopped playing).
  On Linux, `setup` and `build` also build SDL3 (pinned in `tools/fna.json` under `sdl`) and FNA3D (from FNA's checkout) from source with Aether's patches, `tools/sdl.patch` and `tools/fna3d.patch`, and put them in `lib/fnalibs/` over the downloaded ones (cached in `.aether/natives/`; `lib/fnalibs/.aether-rebuilt` records their hashes, which the pin checks accept instead): they add GPU timestamp queries and `FNA3D_GetGPUFrameTimeEXT`, the GPU frame time the profiler shows.
  That needs cmake and a C compiler; without them the downloaded libraries stay, and GPU time reads n/a (as on Windows and macOS).
  The Vulkan terrain extension builds its FNA3D against that SDL too, so it keeps the GPU timing.
  CI artifacts expire after 90 days; the pinned run (from 2026-11-03) expires around 2027-02-01, so re-pin before then or mirror the libraries.
- At startup, `LinuxLaunch.Main` resolves missing assemblies from a DLL next to the client or an embedded resource matching its name.
  Libraries extracted from the game are embedded under their original resource names.
  FNA is copied next to the client.
  `Aether.NativeLibraries` also looks next to the client for native dependencies such as `libsteam_api.so` and `libnfd.so`.
  The game's background pass that JITs every method skips what needs a library .NET can't load (the WeGame SDK is 32-bit); the .NET Framework builds of the embedded libraries also need the `System.IO.Packaging` and `System.Security.Permissions` packages (and `CaptureCamera`'s XNA path `System.Drawing.Common`, which loads but is never called).
  ReLogic is the exception: it's built from `src/ReLogic/` by `client/ReLogic/ReLogic.csproj`, and `client/Terraria/Terraria.csproj`'s `EmbedReLogic` target embeds that build under the same name.
  To add or replace a library, update both the `Reference` and the `EmbeddedResource` in the csproj, and `LIBRARY_RESOURCES` in `tools/aether/decompile.py` if it comes from the game.
- Embedded data files are loaded by exact name through `GetManifestResourceStream`/`Utils.ReadEmbeddedResource`.
  Names like `Terraria.Localization.Content.de-DE.json` look culture-specific to MSBuild, which is why the `src/Resources/*` item has `WithCulture="false"`.
  Without it, 12 language files are split into satellite assemblies and the game can't find them.
- Don't put non-resource files (including `AGENTS.md`) in `src/Resources/`.
  Every file there is embedded.

## Working in the game code

- `src/` is ILSpy output of the game, not its original source.
  Expect compiler-generated names (`num37`, `array4`, `val`), inlined constants (IDs and message types appear as raw numbers), huge methods and `switch`es, and `base.` qualifiers.
  Keep that style when editing nearby code.
- The core files are enormous (`NPC.cs` ~97k lines, `WorldGen.cs` ~88k, `Projectile.cs` ~81k, `Main.cs` ~68k, `Player.cs` ~58k, `Item.cs` ~50k).
  Find things with `grep -n` and read ranges with offsets; never read these files whole.
- **One build for every OS:** Aether's patch to `src/ReLogic/OS/Platform.cs` picks the platform at runtime (`FnaWindowsPlatform`, `OsxPlatform` or `LinuxPlatform`) where Re-Logic's builds hard-wire it.
  For new code, test `Platform.IsWindows` / `IsOSX` / `IsLinux` only for OS behaviour (Win32 calls, paths), and `Program.IsXna` for anything tied to XNA's WinForms window (`Control.FromHandle`, `Form`): the client always runs on FNA, so those branches must stay off on Windows too.
- To turn a raw number into a name, look it up in `src/Terraria/ID/` (e.g. `ItemID.cs`; `ItemID.Search.GetName(id)` at runtime).
- **When the game updates:** `./aether update --check` compares the pin with Steam's current public manifests (anonymous SteamCMD login, exit 1 if there's a newer build).
  `./aether update` then checks for unsaved `src/` edits against the old base, downloads the new Linux build into `.aether/game/`, re-pins `tools/base.json` (version read from the exe, new manifests; macOS/Windows hashes are recorded on their next `download --platform`), rebuilds `.base/` and re-applies the patches.
  If every patch applies, `patches/GAME_VERSION` moves to the new version; otherwise fix the `src/**/*.rej` conflicts and run `./aether diff`, which regenerates the patches and moves it.
  Commit the re-pinned `tools/base.json` together with the patches.
- When the recipe changes: bump `recipe` in `tools/base.json` and run `./aether setup` (not `--base-only`): it checks for unsaved `src/` edits against the old base before rebuilding it.
